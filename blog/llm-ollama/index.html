Ollama Local LLM: How an LLM Ollama Setup Works with OpenClaw

An Ollama local LLM is a model that runs on your hardware, served by Ollama, and called by OpenClaw as a single tag. Here is how to pick that tag and when a hosted model is still the better primary.

An Ollama local LLM is a language model that stays on a machine you control. Ollama downloads the weights, loads them, and answers on a local API, usually port 11434. People also search the same idea as LLM Ollama. The word order flips. The setup does not. You pick a model tag, Ollama serves it, and nothing in the prompt has to leave the box.

OpenClaw sits one layer above that runtime. It is the assistant: memory, skills, chat channels, and scheduled jobs. It does not bake a model into the install. The model is a setting, written as provider/model. When the provider is ollama, the second half is a tag that already shows up in ollama list.

This page is about that pairing. If Ollama is not installed yet, use the Ollama LLM install guide first, then come back here to choose a tag and point OpenClaw at it.

What Is an Ollama LLM?

An Ollama LLM is not a model family named Ollama. Ollama is the runtime. The LLM is the weight file: Llama, Qwen, Gemma, Mistral, Phi, DeepSeek, and the rest of the public library. Ollama downloads that file, applies the quantisation the tag asks for, and serves chat requests.

You can talk to the process two ways. ollama run <tag> is a chat in the terminal. The HTTP API is what other software uses. OpenClaw uses the API. It does not open a terminal for every message you send in Telegram or Discord.

That split is the useful answer to "what is an Ollama LLM". Ollama is not the brain. It is the process that loads a brain and answers requests. Change the tag and the brain changes. Memory, channels, and cron jobs stay put.

Ollama LLM Models That Fit a Normal Machine

Ollama LLM models are tags, not slogans. qwen2.5:7b and qwen2.5:14b are different downloads. The number is the parameter size. A bigger number is usually better at multi-step instructions, and it is always heavier on RAM.

  • 7B to 8B. Llama 3.1 8B, Qwen2.5 7B, and Mistral 7B fit in about 8 GB of RAM or VRAM. They handle chat, summaries, and light tool use.
  • 14B. Qwen2.5 14B is a clear step up for a longer instruction. Plan on 16 GB.
  • 32B and above. A workstation choice. A 70B tag needs a dedicated GPU. On a small VPS, stay at 7B to 8B and keep hard jobs on a hosted model.

Check what is already on disk before you pull another file:

ollama list

Pull one tag you will actually set in OpenClaw. Three extra downloads do not make the assistant smarter. They fill the disk. For a wider comparison of which local model to pick, see the best local LLM guide and the Ollama open source LLM notes.

How OpenClaw Calls an LLM Ollama Setup

OpenClaw addresses the model as ollama/<tag>. The tag must match ollama list, including a size suffix if the name has one. ollama/llama3.1 and ollama/llama3.1:8b are not the same string. Once an allowlist is set, a near miss is rejected instead of quietly falling back.

On the machine that runs the Gateway:

ollama pull qwen2.5:7b
openclaw models list --provider ollama
openclaw models set ollama/qwen2.5:7b

openclaw models set writes the primary model and leaves the rest of the config alone. The usual surprise is a session pin. A chat that already chose a model keeps it until you run /model default. New chats pick up the new primary on the next message. openclaw models status shows the resolved default.

Ollama has to be reachable from the Gateway, usually at http://127.0.0.1:11434. If OpenClaw is on a VPS and Ollama is on your laptop, localhost on the VPS is a different machine. Run both on the same host, or point OpenClaw at the host that is actually serving the model. The install guide shows that base URL line. Do not publish port 11434 on a public interface. The local API has no login by default.

The wider question of which provider is selected, including hosted defaults, is in what LLM OpenClaw uses.

An Ollama Open Source LLM vs a Hosted Model

An Ollama open source LLM is a weight file you can run without sending the prompt to OpenAI, Anthropic, or Google. The privacy gain is real. Prompts stay on the box. There is no per-token invoice from a model vendor.

It is not an automatic upgrade in quality. Hosted frontier models are still better at long tool chains. A local 8B model will drop instructions that a larger hosted model follows. If the agent can run shell commands, a weak local primary is the risky choice, not the safe one. Keep tools on a hosted primary and use the local model for private chat and drafts.

Cost runs the other direction. A hosted primary bills per token. A local primary bills as electricity and the machine. The monthly cost breakdown compares those paths. A private LLM on a small VPS is the middle path: always on, no vendor log of your prompts. Pair it with the local AI assistant setup if you want Telegram on that same model.

When to Skip an Ollama Local LLM

Skip a local model if the machine has under 8 GB of free RAM, if you need image input and the tag is text only, or if a long cron job must not stall. A CPU-only 14B model can take long enough that a scheduled run looks frozen. For those jobs, a small hosted model is the more reliable worker.

Also skip it if you expected "Ollama" to be a single model you just turn on. There is no Ollama model. There is a library. Until you pick a tag, you have not picked an LLM.

What to Do Next

Pull one tag that fits the RAM and set that exact tag in OpenClaw. Confirm with openclaw models status. If the line starts with ollama/, the assistant is on a local model. If OpenClaw is not on a server yet, start with the VPS install guide.

  • An Ollama local LLM is a model tag served by Ollama on your hardware, not a separate product.
  • OpenClaw calls it as ollama/<tag>. The tag must match ollama list.
  • 7B to 8B models fit an 8 GB machine. 14B wants about 16 GB. 70B is a workstation.
  • Do not expose port 11434 to the public internet.
  • Use a hosted primary when the agent runs tools and the local model is too small.
