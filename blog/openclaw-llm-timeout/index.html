OpenClaw Timeout: Fix an LLM Request That Never Returns

An OpenClaw timeout is a clock that ran out. The right fix depends on which clock it was.

An OpenClaw timeout is a clock that ran out, not a broken install. The message shows up when a model stays silent, when a provider request is cut off, or when a caller stops waiting while the run is still going. Change the wrong number and the next job dies at the same second.

OpenClaw is the assistant. The LLM is only the engine for one attempt. Memory, skills, and channels stay put. You change a timeout, a model id, or a fallback. You do not reinstall.

An OpenClaw model timeout and an LLM request timeout are related, and they are not the same setting. Match the log to the clock before you edit config.

What an OpenClaw Timeout Means

Three limits matter on a normal Gateway turn.

The model idle clock aborts a request when no response chunks, and no recognized keepalives, arrive in time. Cloud models get 120 seconds of silence. Self-hosted models get 300 seconds. A separate progress deadline is twice that idle window. Keepalives can hold the socket open without counting as progress.

The provider HTTP clock is models.providers.<id>.timeoutSeconds. It covers connect, headers, body streaming, and the guarded abort for that provider. The first wait for headers is 120 seconds on cloud endpoints and 300 seconds on local or self-hosted ones, unless a lower attempt ceiling cuts it short. TCP and TLS setup still defaults to 10 seconds when that field is unset.

The attempt clock is agents.defaults.timeoutSeconds. The default is 172800 seconds (48 hours) of elapsed time for one model attempt. Tool calls and partial text do not reset it. Set 0 for no execution timer. Provider liveness still applies. A provider timeout cannot outrun this ceiling, so raise the attempt budget if you set a longer provider value. Each fallback gets a fresh budget.

OpenClaw Model Timeout

An OpenClaw model timeout is almost always silence, not a slow stream of tokens. The request was accepted, or the first byte never arrived, and then nothing moved.

Cold local models do this. Ollama may still be loading weights, and a 14B model on a small VPS can sit quiet past the first-event window. A hosted stall looks the same. The log says LLM timeout while the process is alive. If the tag was never pulled, start with the Ollama LLM guide. A stream that keeps emitting tokens is different: the idle clock is for gaps, and a long answer is limited by the attempt budget. Raising only the agent timeout will not save a model that never sends the first token.

LLM Request Timeout

An LLM request timeout is the provider HTTP limit. Put it on the provider that is actually slow:

{
  "models": {
    "providers": {
      "ollama": {
        "timeoutSeconds": 600
      }
    }
  }
}

Use the provider id you already configured. LM Studio, vLLM, and other OpenAI-compatible local servers use the same field next to baseUrl. A value of 600 gives a cold model ten minutes. It does not raise the 48 hour attempt budget. A provider timeout of 600 with an attempt budget of 120 still ends at 120. Leave keys in provider auth. The field is only seconds.

An instant failure is not this setting. A wrong model id, a refused key, or a dead base URL fails before the long clock matters. Ten seconds of TCP usually means the host was unreachable. A self-hosted LLM that is not listening looks like a timeout if you only read the last log line.

When the Attempt Budget Ends

The attempt budget covers planning, tool calls, and the reply for one model. The 48 hour default is enough for chat. It does not excuse a stuck tool. Progress does not renew the budget, and a stored override such as 600 replaces the default for every attempt.

Return to the default, or set a 12 hour limit, from the CLI:

openclaw config unset agents.defaults.timeoutSeconds
openclaw config set agents.defaults.timeoutSeconds 43200

A terminal timeout is a failed turn. Earlier tool output stays in the transcript and does not count as a finished reply. ask_user does not pause the attempt budget. Approval waits do, and resolving them resumes the same budget.

A Wait Timeout Is Not a Dead Run

agent.wait defaults to 30 seconds, and timeoutMs overrides it. The wait does not cancel the run. A response that is only a run id and status: "timeout" means you should wait on that same run again. timeoutPhase: "gateway_draining" is a shutdown. timeoutPhase: "queue" with providerStarted: false means the model has not started. That is not an LLM request timeout. The openclaw agent command has a separate 600 second fallback for that command only. A chat that stops at ten minutes in the CLI, and continues in the Gateway, is this split.

Cron and the OpenClaw LLM Timeout

Cron starts its own timer when execution begins. Fallback does not reset it. At the deadline, OpenClaw aborts the run and cleans up so the lane does not stay stuck. Tune the schedule in OpenClaw cron jobs, not only the model timeout.

With an explicit cron timeout, a silent cloud model is capped at 60 seconds so the next fallback can still start. Loopback endpoints keep local idle behavior. A self-hosted provider on a network base URL uses the 300 second watchdog, capped by that cron timeout. A 48 hour agent budget will not save a two-minute job. Shorten the prompt or use a faster model. Retrying the same slow model is how an OpenClaw LLM timeout becomes a daily failure.

Fix the Clock That Fired

  1. Read the error first. Silence, a refused connection, a queue phase, and an attempt budget are different fixes.
  2. Confirm the model id. A missing Ollama tag looks like a hang, then a timeout.
  3. For a cold local model, set models.providers.<id>.timeoutSeconds for the first token. Raise the agent timeout only if it is lower.
  4. If tokens keep arriving but the turn never ends, raise the attempt budget or shrink the task.
  5. Add a fallback on another provider. Each fallback gets a full attempt budget. Cancelling stops the chain.
  6. Test with a prompt that must call a tool, not a greeting.

Use a local primary for private notes and a hosted fallback for the turn it cannot finish. A slow first load needs a provider timeout. A model that ignores tools needs a different model, not a longer clock. See choosing an OpenClaw LLM and the cheapest LLM for OpenClaw before you leave a strong fallback on every cron run.

Leave the 48 hour default alone unless a job needs a shorter cap. A low agent timeoutSeconds is the usual self-inflicted OpenClaw timeout: every real task dies on the same second, and the model was fine.
