What LLM Does OpenClaw Use?

OpenClaw does not ship with one locked language model. The LLM that answers your chats is a setting, written as provider/model, and you can change it without reinstalling.

Most assistants hide this choice. ChatGPT is OpenAI. The Claude app is Anthropic. Gemini is Google. OpenClaw is a self-hosted assistant, so the model is yours to pick during setup and yours to swap later. If a friend says "OpenClaw uses GPT" or "OpenClaw uses Claude," they are describing their config, not a product default that applies to every install.

Below is where the model is stored, what a fresh OpenAI sign-in selects, and the commands that change it.

What Model Does OpenClaw Use by Default?

There is no universal OpenClaw LLM. Until you connect a provider, there is nothing to call. The primary model lives at agents.defaults.model.primary in ~/.openclaw/openclaw.json. You can also set agents.defaults.model as a plain string. Either way the value looks like openai/gpt-6-astra or anthropic/claude-opus-5-5: provider, a slash, then the model id.

openclaw onboard writes that field after you pick a provider. Hosted options include OpenAI, Anthropic, Google, xAI, and OpenRouter. Local runtimes include Ollama, LM Studio, llama.cpp, and vLLM. Adding a key does not change the primary by itself. Credentials and the selected model are separate steps.

One path does have a catalog default. On OpenClaw 2026.9, a fresh OpenAI API-key setup, or a fresh ChatGPT/Codex OAuth setup, selects openai/gpt-6-astra when no primary is set yet. The same ref is the fresh default for the native Codex harness. If the account cannot use that generation, set openai/gpt-5.5 yourself. OpenClaw does not silently downgrade, and signing in again keeps an explicit primary you already chose.

That OpenAI default does not apply to other providers. An Anthropic, Google, xAI, or Ollama install stays on whatever you set. A current Anthropic example is anthropic/claude-opus-5-5. If a key does not expose the model you expected, run openclaw models list --provider openai (or the provider you actually use).

How to See Your Current OpenClaw LLM

On the machine that runs the Gateway:

openclaw models status
openclaw models list

openclaw models status prints the resolved default, the fallback list, and whether those routes look usable. It does not show a per-chat override. openclaw models list is the catalog. Add --provider openai or --provider ollama to narrow it. In chat, /model status shows this session. A pin is why a config edit can look like it did nothing: the old session model stays until you clear it.

How to Change the OpenClaw Default Model

For a permanent change, set one field:

openclaw models set openai/gpt-6-astra
openclaw models set anthropic/claude-opus-5-5

openclaw models set updates the model config and leaves the rest of the file alone. You can also run openclaw configure --section model, or edit agents.defaults.model directly. Prefer a small edit. Replacing the whole config is how people wipe channels, skills, and auth by accident.

Chat commands are scoped, which matters if you only want to test:

  • /model openai/gpt-5.5 -s changes this session only.
  • /model openai/gpt-5.5 -a (owner or admin) updates this session and the agent default.
  • /model openai/gpt-5.5 -g updates this session and the global default.
  • A bare /model name, with no flag, stays in the current session unless you changed model selection scope.

Changing agents.defaults.model.primary does not unpin sessions that already picked a model. Those pins stay until you clear them with /model default. New chats, and sessions that were never pinned, pick up the new primary on the next run. You do not restart the Gateway for a normal model switch.

If the reply is "Model ... is not allowed," agents.defaults.modelPolicy.allow is a non-empty allowlist. Add the exact ref, add a provider wildcard such as openai/*, or empty the list. The model picker and /model both obey that list.

The multi-model guide covers aliases, per-agent models, and running more than one provider side by side. This page stays on the question of which model is actually selected.

Which LLM Does OpenClaw Use for Side Jobs?

The primary model is the one you talk to. Other slots exist so a short internal call, or a dead route, does not have to use that same model.

Fallbacks live in agents.defaults.model.fallbacks and are tried in order when the primary route fails. A model you picked with /model is strict: if that exact ref is down, the run fails instead of hopping to another model. Configured defaults and cron jobs still use the fallback list unless the job sets its own.

agents.defaults.utilityModel is optional. It covers short internal work such as session titles. Leave it unset and OpenClaw uses the provider's small-model default when one exists: gpt-5.6-luna on OpenAI, claude-haiku-4-5 on Anthropic. Otherwise it uses the primary. agents.defaults.imageModel matters only when the primary cannot accept images. Skip it for normal text chat.

Use a Local Model Instead of a Hosted LLM

You do not have to point OpenClaw at a hosted API. Ollama is the shortest local path. Install it, pull a model, then set the tag OpenClaw actually lists:

ollama pull gemma4
openclaw models list --provider ollama
openclaw models set ollama/gemma4

Use the exact tag from the list. A display name is not enough once an allowlist is on. The same pattern works for LM Studio, llama.cpp, and vLLM once that provider is configured. Prompts stay on hardware you control, which is the point of a local assistant. Smaller quantized models are weaker at tool use, so if the agent can run commands, prefer a larger local model or keep tools on a stronger hosted primary.

What to Pick in Practice

Use the strongest model you can afford for the main agent, especially if it has tools and reads untrusted input. Put a cheaper model on fallbacks, or on a second agent that only handles routine chat. On a brand-new OpenAI setup with nothing set, current OpenClaw selects openai/gpt-6-astra. For private inference, point the primary at an ollama/ tag and accept the hardware limit. Leave the utility model unset unless side calls are getting expensive.

A hosted primary bills per token. A local primary bills as electricity and a VPS. The monthly cost breakdown compares those paths before you lock a model in.

If OpenClaw is not installed yet, start with the VPS install guide, connect one provider, then run openclaw models status before you change anything else. You will know exactly which LLM is answering.

Summary

  • OpenClaw has no single built-in LLM. The model is your primary setting, stored as provider/model.
  • Check it with openclaw models status. List options with openclaw models list.
  • A fresh OpenAI sign-in with no primary selects openai/gpt-6-astra on OpenClaw 2026.9. Other providers do not inherit that default.
  • Change it with openclaw models set provider/model. Use /model ... -s to test in one chat.
  • Existing session pins stay until you run /model default.
  • Fallbacks, a utility model, and Ollama are optional. They replace the primary only if you point the primary at them.
