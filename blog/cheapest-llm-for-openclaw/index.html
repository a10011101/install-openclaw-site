Cheapest LLM for OpenClaw in 2026

The cheapest LLM for OpenClaw is the model that finishes ordinary work for the least money, not the one with the lowest number on a price page. Local weights, small hosted models, and a stronger fallback each win in a different case.

People shopping for the cheapest LLM for OpenClaw usually compare two numbers: dollars per million tokens, or "free if I run it myself." Both numbers lie if you stop there. A model that misses tool calls, times out, or writes a draft you throw away is not cheap. You pay again on the retry, and you pay in time.

OpenClaw does not lock you to one vendor. The model is a setting. Memory, skills, and chat channels stay when you change it. That is why cost is a routing decision, not a forever contract. If you still need a quality shortlist, start with the best open source LLM for OpenClaw, then use this page to decide what you can afford to run every day.

What "Cheapest" Should Count

Count three bills, not one.

The first is the model bill. Hosted APIs charge for input and output tokens. Local models charge nothing per token, but the VPS or GPU box is already on the invoice. The second is failure cost. If the cheap model cannot call a tool, OpenClaw retries or you rerun the task on a better model. The third is your time. A free model that needs a rewrite is more expensive than a small paid model that ships the note on the first pass.

For a personal assistant that checks mail, drafts a short reply, and files a note, a 7B to 14B local model is often the cheapest LLM for OpenClaw across a month. For a burst of long research you run twice a week, a cheap hosted model can cost less than keeping a bigger GPU warm.

Local Models: Cheap After the Server

Once the machine is paid for, extra chats are close to free. That is the real case for Ollama and other local LLMs. A 7B or 14B model on a small VPS handles reminders, summaries, and simple file edits without an API line item. See OpenClaw cost per month for where the rest of the spend goes: the server, backups, and any paid channels.

Local stops being cheap when the box is oversized for the work. A 70B model that sits idle still burns RAM and power. If your daily tasks fit in 8 to 16 GB, do not rent a GPU "just in case." Keep the large model off the default path.

Quality still matters. A tiny model that ignores instructions will make you repeat the prompt. Give the candidate the same job you actually run: read a file, call one tool, write a short result. If it finishes, it is a candidate for the cheap seat. If it wanders, it is not free. It is a tax.

Cheap Hosted APIs

Hosted models win when you have no GPU and you do not want to tune weights. Prices move every month, so do not hard-code a vendor into your plan. Sort by three filters:

  • Tool use. OpenClaw spends a lot of turns calling tools. A bargain chat model that cannot follow a tool schema will fail the jobs that matter.
  • Context you really send. Stuffing the whole history into every call makes a "cheap" model expensive. Trim the prompt before you upgrade the model.
  • Rate limits. A low per-token price with a tiny quota just queues your assistant.

Small hosted models are the right cheap API for everyday chat. Keep a stronger model for coding, long synthesis, or anything you would be annoyed to redo. OpenClaw already lets you point a session at a different model without rebuilding the assistant. That split is described in how OpenClaw works with multiple models.

A Cheap Default and a Strong Fallback

The cheapest setup is rarely one model. It is two.

Put the inexpensive model on the default path: heartbeat checks, short replies, classification, "file this note." Put the capable model on the hard path: multi-step coding, messy research, anything that failed once on the small model. You pay the high rate only when the cheap model is the wrong tool.

Do not flip the order. If the strong model is the default, every "hey, are you there?" burns the expensive context window. If the weak model is the only model, you will rerun the hard tasks by hand and the savings disappear.

Hidden Costs That Blow the Budget

Four habits erase a cheap model:

  • Retries. A timeout or a malformed tool call spends the tokens and produces nothing. Fix the timeout and the prompt before you buy a bigger model.
  • Long context by default. Sending yesterday's whole transcript into a one-line question multiplies the input bill. Keep memory in files and pull only what the task needs.
  • Reasoning models for chores. A reasoning model can be worth it for a hard plan. It is waste on "what time is the post due?"
  • Idle capacity. A GPU you rented for one weekend project is the opposite of cheap if it stays on all month.

Measure a normal day, not a demo. Note how many turns were chat, how many were tools, and how many you redid. That log tells you whether the cheapest LLM for OpenClaw is local, hosted, or a split.

A Practical Cheap Setup

For most self-hosted installs in 2026, start here:

  1. Run a 7B to 14B open model through Ollama on the same server as OpenClaw.
  2. Set that model as the default. A typical line looks like this:
model: ollama/qwen2.5:7b

Restart after the change. Memory and skills stay. If replies get sloppy, step up to a 14B tag before you jump to 32B or 70B.

  1. Keep one stronger API model available for the sessions that need it. Switch that session only. Do not make it the default.
  2. Watch retries for a week. If the local model fails the same tool call twice, that job belongs on the stronger model, not on a third retry.

That pattern beats hunting for a single "cheapest LLM" banner. The winner is the smallest model that completes your real tasks, with a more expensive model waiting for the exceptions.
